# Contributing to General-

Welcome! This guide explains how our computer security group collaborates in this repository.

## 📋 Workflow

1. **Open an Issue** before starting any significant work — describe what you plan to do.
2. **Create a branch** from `main` named `your-username/short-description`.
3. **Make your changes**, commit with clear messages.
4. **Open a Pull Request** and request at least one group member to review it.
5. Once approved, **merge** into `main`.

## 🌿 Branch Naming

| Type | Example |
|------|---------|
| Feature / assignment | `alice/aes-implementation` |
| Bug fix | `bob/fix-xss-script` |
| Notes / research | `carol/network-scanning-notes` |

## 💬 Commit Messages

Use short, descriptive messages:
```
Add Caesar cipher implementation
Fix SQL injection example script
Update README with CTF resources
```

## 🔍 Code Review

- Be respectful and constructive.
- Focus on correctness, security, and readability.
- All PRs should be reviewed by at least one other group member before merging.

## 🐛 Issues

Use GitHub Issues to:
- Assign tasks to group members
- Report bugs or problems in shared scripts
- Propose ideas or topics to explore

## ⚠️ Security & Ethics

- **Never** commit real credentials, API keys, or passwords.
- Only use shared tools and exploits in authorized lab/CTF environments.
- Follow your institution's academic integrity policy.
